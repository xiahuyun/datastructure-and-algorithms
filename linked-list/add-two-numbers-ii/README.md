# 445. 两数相加 II（Add Two Numbers II）

> https://leetcode.cn/problems/add-two-numbers-ii/description/

## 题目描述

给出两个非空链表，表示两个非负整数。数字按**正序**存储：头节点是最高位，每个节点存一位数字。
将两数相加，返回同样正序存储的结果链表。

```
输入: (7 -> 2 -> 4 -> 3) + (5 -> 6 -> 4)    即 7243 + 564
输出: 7 -> 8 -> 0 -> 7                       即 7807
```

**进阶（follow-up）**：如果输入链表不能修改（即不允许翻转链表）呢？

## 核心矛盾

第 2 题（两数相加）逆序存储，头节点恰好是个位，顺着链表走就是从低位加到高位，与竖式加法完全一致。
本题正序存储，头节点是**最高位**，顺序遍历的加法方向与进位传递方向相反：

> 加法必须从低位做起，而链表只能从头（最高位）遍历。

三种解法都在解决同一件事——**想办法从低位开始处理**。

## 思路一：反转链表（addTwoNumbersReverse）

把两条输入链表反转，问题退化成第 2 题（头节点变个位），做完竖式加法后把结果再反转回来。
最直白，但**会修改输入链表**，违背 follow-up 的要求。

## 思路二：栈（addTwoNumbersStack）

栈（LIFO）天然倒转访问顺序：顺序入栈后，弹出的顺序恰好是从低位到高位。
两条链表的值分别入栈，循环弹栈逐位相加（弹空的一侧按 0 处理，自动对齐长度差），
每算出一位就把新节点**头插**到结果头部，结果天然正序，最高位的进位走同一条头插逻辑。
**不修改输入链表**，代价是 O(m+n) 的栈空间。

## 思路三：递归（addTwoNumbersRecursive）

递归先一路走到链表尾，"归"的阶段恰好从低位（尾部）回到高位（头部），
进位作为返回值向高层传递——递归本身就是"倒着的遍历"。
先算长度差 diff 并保证 l1 不短于 l2：diff > 0 时 l2 按前导零处理，对齐后两两同步前移。
**不修改输入链表**，代价是 O(n) 调用栈（题目约束链表最长 100，递归深度安全）。

## 三方案对比

| 方案 | 修改输入 | 时间 | 额外空间 | 一句话评价 |
|---|---|---|---|---|
| 反转链表 | 会 | O(m+n) | O(1) | 最直白，复用第 2 题的加法核心 |
| 栈 | 不会 | O(m+n) | O(m+n) | 不动输入的最常规解法 |
| 递归 | 不会 | O(m+n) | O(n) 调用栈 | 用"归"阶段倒转处理顺序，最优雅 |

## Follow-up 回答：不翻转链表可以吗？

**可以**。栈和递归两种实现都不修改输入链表（见 `addTwoNumbersStack` 和 `addTwoNumbersRecursive`）。
另存在不修改输入且 O(1) 额外空间的进阶解法——先按位无进位相加，再把末尾连续的 9 段整体回填进位（思路见官方题解，本文不实现）。

## 运行与测试

```bash
go run main.go   # 演示输出（同一组数据分别跑三种实现，结果应一致）
go test -v       # 单元测试
```

测试覆盖的用例（三种实现跑同一组）：

- LeetCode 两个官方示例（7243+564=7807、243+564=807）
- 两链表长度不等（5+998=1003，覆盖递归解法中"保证 l1 更长"的交换分支）
- 最高位进位，结果多一个节点（99+1=100）
- 0+0=0
- 100 个节点的边界大数（两个 `10^100 - 1` 相加，全链进位 + 结果 101 个节点）
